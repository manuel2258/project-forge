Cache textures by content hash
The asset step keys its cache on the commit hash, so every push rebuilds all 212 textures and the step takes six to seven minutes.
Keying each texture on a hash of its source file and its import settings rebuilds only what changed. The import settings live in
assets/import.toml
, so a change there invalidates every texture it covers, which is correct.
Done when
a push that touches no texture skips the step in under 20s
changing one PNG rebuilds one texture
the cache survives a runner restart
Out of scope
Audio and level files, which are copied, not built.

Cache textures by content hash
The asset step keys its cache on the commit hash, so every push rebuilds all 212 textures and the step takes six to seven minutes.
Keying each texture on a hash of its source file and its import settings rebuilds only what changed. The import settings live in
assets/import.toml
, so a change there invalidates every texture it covers, which is correct.
Done when
a push that touches no texture skips the step in under 20s
changing one PNG rebuilds one texture
the cache survives a runner restart
